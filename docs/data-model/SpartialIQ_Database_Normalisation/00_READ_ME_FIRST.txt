SpartialIQ (Vungu RDC) - Database Normalisation Package
=======================================================
29 September 2026

This package documents the normalisation of the SpartialIQ PostgreSQL/PostGIS
database: what the tables are, how they relate, and the scripts that made
the change.


WHAT IS IN THIS PACKAGE
-----------------------
1_Data_Dictionary/
  DATABASE_Data_Dictionary.docx   Start here. Every schema, table and column
                                  set out in tables: type, nullability, primary
                                  and foreign keys, description, row counts,
                                  and every lookup table with its allowed values.
  DATABASE.md                     The same dictionary as plain text (Markdown),
                                  including an entity-relationship diagram.
  SSOT-database.md                Which table is the single source of truth for
                                  each business concept, and what it replaced.

2_Model_Documents/
  01_Conceptual_Model.docx        Business concepts and relationships.
  02_Logical_Model.docx           Entities, keys, normal forms, permit states.
  03_Physical_Model.docx          PostgreSQL/PostGIS implementation.
  04_Expected_Needed_And_Delivered_Zimbabwe.docx
  Supervisor-Review-Rectification-Summary.docx

  Note: documents 01-03 were written before this normalisation. Where they
  differ from the data dictionary (e.g. they still mention a user_profiles
  table), the data dictionary is the current physical model.

3_Migration_Scripts_SQL/
  130_ref_lookup_schema.sql       Lookup ("reference") tables for every
                                  controlled vocabulary.
  131_consolidate_and_shrink.sql  Removes duplicated tables and columns.
  132_data_dictionary_comments.sql  Stores a description on every table.
  Each script starts with a header explaining exactly what it changes.


WHAT THE NORMALISATION DID
--------------------------
1. Every fact is stored once (third normal form).
   - The peri-urban planning zones were stored in three separate tables;
     they are now one table, referenced by an integer foreign key.
   - Duplicate columns were removed from users (name / full_name,
     last_login / last_login_at, active / status) and from stands
     (status_code, use_scale_code, zone_type_cache, zone_id_int).
   - Ward, district, province and country names are no longer copied into
     other tables; they are looked up through the administrative hierarchy
     wards -> districts -> provinces -> country, now enforced by foreign keys.
   - Values that can be calculated (a stand's label point, a zone's area in
     hectares) are generated by the database from the geometry, so they can
     never disagree with it.

2. Every controlled vocabulary is a table.
   134 hard-coded lists of allowed values (statuses, types, categories) and
   two enumerated types were replaced by 117 lookup tables in a dedicated
   "ref" schema. Each business column references its lookup table by foreign
   key, so a new status is added as a row, not by changing the database design.

3. The database was reduced in size.
   - Operational tables: 178 -> 166 (unused and duplicate tables removed).
   - 12 redundant indexes removed; numbers that had been stored as text are
     now stored as numbers.
   - Database size: 150 MB -> 117 MB (measured on a full copy of the
     database with the migrations applied and the storage compacted).

4. Everything is documented inside the database itself.
   Every schema, table and view carries a description, and the data
   dictionary in this package is generated automatically from those
   descriptions and the database catalogue.


HOW IT WAS CHECKED
------------------
- Each script was run twice on a full copy of the database and on a copy
  without the map layers, to confirm it is safe to re-run.
- 145 read endpoints of the application were compared before and after:
  none that worked before now fail.
- 25 create/update/delete checks on the changed tables all passed, and all
  23 automated unit-test suites pass.
- The review also found and fixed several existing faults, including stand
  detail pages failing, user suspension and deletion failing, and zones that
  could not be created.
