# PostGIS Vector Tile Maps — Design

**Date:** 2026-05-20
**Status:** Approved (design)
**Author:** Muna18Madzinga

## Problem

The webapp's maps draw from two thin, inconsistent sources: a QGIS Server
OGC bridge (`/ogc/*` WMS/WFS) and a handful of sparse Gweru-specific sample
tables (`gweru_roads`, `gweru_schools`, `gcc_boundary`, …). The rich
country-wide spatial dataset in `zimbabwe.gpkg` — 24 layers, 5.7M buildings,
210K roads, full admin boundaries (1 country / 10 provinces / 91 districts /
1,961 wards), landuse, hydrology, and POIs — is not used by any map.

The goal: every map in the app renders this national dataset, served from
PostGIS by the backend. The data is already imported into PostGIS.

## Goals

- Serve the full `zimbabwe.gpkg` dataset from PostGIS to all maps.
- Deliver it as Mapbox Vector Tiles (MVT) generated by PostGIS `ST_AsMVT`,
  consumed natively by MapLibre GL.
- One shared frontend module so all ~10 map views adopt the data uniformly,
  without rewriting the large existing map components.
- Keep the existing QGIS Server (`/api/qgis`, `/ogc/*`) intact and selectable;
  PostGIS vector tiles become the primary data path, QGIS stays alongside.

## Non-Goals

- Importing the GeoPackage (already in PostGIS — verified as the first
  implementation step; import only becomes a task if tables are missing).
- Removing QGIS Server or the OGC bridge.
- Changing application data tables (`land_parcels`, `stands`, development
  applications). Only basemap/context data is in scope.
- Pre-generated static tiles (`.pmtiles`) — rejected; not PostGIS-backed at
  request time.

## Architecture

```
zimbabwe.gpkg (already imported)
        │
        ▼
PostGIS tables (24 layers) ──GIST indexes──┐
        │                                  │
        ▼                                  ▼
Fastify /api/tiles route          spatialLayers.ts registry
  ST_AsMVT + ST_AsMVTGeom         (allowlist + zoom tiers + style)
        │
        ▼  .pbf  (Redis-cached, 7-day TTL)
MapLibre GL  ◄── addVunguBasemap(map)  ◄── src/map/vunguBasemap.ts
        ▲
        └── every map view calls addVunguBasemap on load
```

QGIS Server `/api/qgis` and `/ogc/*` remain registered and unchanged.

## Backend

### Tile service — `src/routes/tiles.ts` (prefix `/api/tiles`)

- `GET /:layer/:z/:x/:y.pbf` — returns an MVT. Query shape:
  ```sql
  SELECT ST_AsMVT(t, :layer) FROM (
    SELECT ST_AsMVTGeom(ST_Transform(geom, 3857),
                        ST_TileEnvelope(:z,:x,:y), 4096, 64, true) AS geom,
           <whitelisted attributes>
    FROM <table>
    WHERE geom && ST_Transform(ST_TileEnvelope(:z,:x,:y), 4326)
      <optional low-zoom filter>
  ) t WHERE t.geom IS NOT NULL;
  ```
  `:layer` is validated against the registry — the registry is the table
  allowlist, so the table name is never raw user input (no SQL-injection
  surface). Empty result → `204`. Unknown layer → `404`. Bad `z/x/y` → `400`.
- `GET /layers` — returns the registry as the layer catalog (id, title,
  geometry type, group, default style, min/max zoom, feature count).
- `GET /:layer/:id` — single feature as GeoJSON, for click-to-inspect popups.

### Caching & performance

- Rendered tiles cached in Redis (`@fastify/redis`, already registered),
  key `tile:{layer}:{z}:{x}:{y}`, ~7-day TTL.
- Long `Cache-Control` header so browsers cache tiles too.
- Zoom-gating (see registry) prevents querying dense layers at low zoom.
- Startup check confirms a `GIST` index exists on each registered geom
  column; logs a warning if missing (migration creates them).

### Layer registry — `src/config/spatialLayers.ts`

Single source of truth. One entry per GeoPackage layer:

```ts
{
  id: 'buildings',
  table: 'buildings',
  geomColumn: 'geom',
  geomType: 'polygon',          // polygon | line | point
  group: 'structures',          // admin | structures | transport | hydro | landuse | poi
  title: 'Buildings',
  attributes: ['fid', 'name', 'type'],   // whitelist exposed in tiles
  minzoom: 14, maxzoom: 22,
  lowZoomFilter: null,          // optional SQL WHERE fragment for low zoom
  defaultStyle: { /* MapLibre paint/layout fragment */ }
}
```

Zoom tiers:

| Group | Layers | Zoom |
|---|---|---|
| admin | country, provinces, districts, wards | 0–22 |
| landuse | landuse, admin_areas, places_areas | 8+ |
| hydro | water_areas, waterways, protected_areas, natural_areas | 8+ |
| transport | roads, railways | 8+ (major roads only below z12 via `lowZoomFilter` on `fclass`) |
| structures | buildings, traffic_areas, transport_areas, pois_areas, places_of_worship_areas | 14+ |
| poi | places_points, pois_points, traffic_points, transport_points, natural_points, places_of_worship_points | 14+ |

### Verification step (first implementation task)

Introspect the DB's `geometry_columns` view to confirm actual table names,
geometry column, and SRID of the imported data. GeoPackage table names are
generic (`roads`, `buildings`, …); `ogr2ogr` may have kept, lowercased, or
prefixed them. The registry is populated from what actually exists. A missing
table escalates to an import sub-task.

### Migration — `074_spatial_tile_indexes.sql`

Creates any missing `GIST` index on each registered geom column, plus
attribute indexes needed by low-zoom filters (e.g. `roads.fclass`).

### Backend cleanup

`/spatial-data/*` routes reading sparse `gweru_*` tables (`land-parcels`,
`coordinate-points`, `roads`, `planning-boundaries`) are repointed to the
national tables or retired — callers are grepped first before any removal.
Application-specific tables are untouched.

## Frontend

One module, every map calls it — so "replace all maps" does not mean
rewriting the large map components.

### New files

- `src/services/vectorTiles.ts` — client: `getTileLayerCatalog()`,
  `getFeature(layer, id)`, `tileUrl(layer)` →
  `/api/tiles/{layer}/{z}/{x}/{y}.pbf`.
- `src/map/vunguBasemap.ts` — `addVunguBasemap(map, options?)`. Adds one
  `vector` source per registry group plus styled `fill`/`line`/`circle`/
  `symbol` layers, correctly ordered (admin outlines on top, buildings/
  landuse at the bottom). Idempotent. Options select which groups show and
  whether labels render. Wires hover cursor + click → `getFeature` → emits
  a normalized `feature-click` event.
- `src/map/vunguBasemapStyle.ts` — MapLibre style fragment (paint/layout per
  layer), generated from the registry's `defaultStyle` so backend and
  frontend stay in sync.

### Store changes — `useSpatialStore`

- New `loadTileLayers()` action backed by `/api/tiles/layers`.
- New `toggleTileLayer(id)` flipping MapLibre layer `visibility`.
- Existing OGC/QGIS layer logic stays; tile layers are added to
  `allAvailableLayers` so panels list both QGIS and PostGIS layers.

## Rollout across map views

Each view keeps its UI and purpose; only the data source changes — call
`addVunguBasemap(map)` on load, drop dead `gweru_*` fetches.

| View / component | Change |
|---|---|
| `GISMapView.vue` | Add basemap; layer pills bind to tile layers |
| `VunguMapView.vue` | Replace default QGIS WMS load with tile basemap; keep QGIS layers as optional toggles |
| `QGISMapView.vue` | Keep QGIS WMS path; add tile basemap as base context |
| `MapExplorer.vue` | Catalog from `/api/tiles/layers`; toggles drive tile visibility |
| `InteractiveMap.vue` | Add `addVunguBasemap`; remove sparse `gweru_*` GeoJSON loads |
| `SpatialMapCore.vue` | Add basemap beneath development-application overlays |
| `ParcelSelectorMap.vue` | Add basemap as parcel-selection context |
| `citizen/sections/MapSection.vue` | Add basemap |
| `gis-officer/sections/*` (Zoning, ApplicationMapping, EnforcementMapping, EnvironmentalConstraints) | Add basemap; constraint queries hit `/api/tiles/:layer/:id` |

## Error handling

- Unknown layer → `404`; bad `z/x/y` → `400`; empty tile → `204` (MapLibre
  renders blank, no error).
- DB query failure → `500`, logged via `fastify.log`; the failed tile is
  silent and the rest of the map stays usable.
- Frontend: `/api/tiles/layers` failure shows the existing "service
  unavailable" panel state; maps still render loaded layers.
- `addVunguBasemap` wraps each `addSource` in try/catch so one bad group
  never blanks the map.

## Testing

- Backend unit: registry validator; tile SQL builder.
- Backend integration: `GET /api/tiles/:layer/:z/:x/:y.pbf` for one layer per
  geometry type — assert non-empty `.pbf`, `204` on empty, `404` on bad layer.
- Frontend unit: `vectorTiles.ts` URL building; `vunguBasemapStyle`
  generation; `addVunguBasemap` registers expected sources/layers on a mock
  `Map`.
- Manual: load each rolled-out view, confirm national data renders and
  click-inspect works.

## Implementation sequence

1. Verify imported PostGIS tables; build the layer registry.
2. Migration `074` — spatial indexes.
3. Backend `/api/tiles` route + Redis caching.
4. Frontend shared module (`vectorTiles.ts`, `vunguBasemap.ts`,
   `vunguBasemapStyle.ts`) + store actions.
5. Roll out map views one at a time, each independently verifiable.
6. Backend cleanup of dead `gweru_*` `/spatial-data/*` routes.
